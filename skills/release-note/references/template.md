# 版本說明範本與例子

版本說明產出為 Markdown 格式，位置：`docs/release-notes/<版本號>.md`。

## 範本結構

```markdown
# <版本號> 版本說明

## 新功能

- <功能描述，一句敘述>

## 改進

- <改進描述，一句敘述>

## 問題修正

- <問題簡述與修法>

## 重要變更與升級注意

（僅在有 breaking change 時出現）

**受影響功能**：<描述>

**升級步驟**：
1. <步驟>
2. <步驟>
```

## 撰寫指引

**新功能**
- 從 `feat` 類型的 commit 生成
- 一行一項，用白話文簡述功能價值
- 不出現 API 代號、參數名稱等內部細節
- 例：
  - ✓ 支援 CSV 批量匯入
  - ✗ 新增 `POST /api/v2/import` endpoint，支援 `multipart/form-data`

**改進**
- `perf` 類型的 commit 全數列入；`refactor` 只在對使用者有可感知效益（如速度改善、穩定性提升、介面改善）時列入，純內部重構略去
- 突出使用者可感知的效益，改寫為使用者視角
- 合併相似改進，避免逐筆列舉
- 例：
  - ✓ 提升報表生成速度 50%
  - ✗ 優化資料庫查詢效率
  - ✗ 抽出共用的分頁邏輯（純內部重構）

**問題修正**
- 從 `fix` 類型的 commit 生成
- 簡述問題現象與解決方案
- 若問題嚴重或影響多數使用者，特別標注
- 例：
  - ✓ 修復在某些瀏覽器上無法上傳大檔案的問題
  - ✗ Fixed file upload issue

**重要變更與升級注意**
- 僅在有 breaking change 時出現，不應省略
- 「受影響功能」簡明說明變更的範圍
- 「升級步驟」具體列舉使用者需採取的行動
- 例：
  ```
  **受影響功能**：舊版 API（v1）將停用，需遷移至 v2

  **升級步驟**：
  1. 更新依賴包至 2.0.0 版本
  2. 將 `import { oldAPI }` 改為 `import { newAPI }`
  3. 執行資料遷移腳本：`npm run migrate:v2`
  4. 測試整合點後上線
  ```

## 無效輸出示例

以下情況表示 skill 執行有誤，應當停止並回報：

- 包含 commit hash
- 包含內部代號或技術術語未翻譯
- 照搬 commit 原文而非改寫為使用者視角（如「抽出共用邏輯」應說明對使用者的效益）
- 出現「修復 bug」等籠統描述而非具體問題
- 列舉純內部重構（如程式碼結構調整）為改進項
- breaking change 節點省略或描述不完整
- 版本號與檔名不符
- 文件標題非「<版本號> 版本說明」格式
