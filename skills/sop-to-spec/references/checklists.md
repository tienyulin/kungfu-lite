# 清單集

## 追問清單（Step 3，寫每個 endpoint 時逐題確認，答案寫進 spec）

- 每個選填欄位：未提供時的行為？
- 每個比較條件：邊界含不含等號？相等時怎麼處理（排序的平手規則）？
- 同一資源有多種指定方式（id、名稱、時間等）時：誰負責解析、解析失敗回什麼、
  每種方式都有 request 範例與測試案例？
- 操作耗時：sync 還是 202？逾時誰負責？
- 並發：兩個 request 同時操作同一資源會怎樣？（有防護，或無防護＋說明原因）
- 冪等：同一個 request 執行兩次，第二次回什麼？
- 執行中斷：外部系統在執行途中斷線或逾時，回什麼、狀態算什麼？
- 有副作用的前置動作（執行前先修改設定之類）：必須在其餘檢查全部通過後才執行，
  注定失敗的 request 不得留下副作用
- 固定字串與 token：給字面值，並指明常數檔
- 枚舉型欄位（錯誤原因、狀態字等）：值域在 spec 裡完整列出——寫「見某檔案」
  「等」「…」都算沒寫，實作者會自己編值

## 自檢清單（Step 4）

- [ ] 可讀性：不懂技術的人讀第 1–3 節，能說出這個 API 做什麼、誰能用、
      最需要小心的操作是哪個
- [ ] 一致性：Endpoint 一覽與各 endpoint 節一一對應；範圍外與 SOP 的範圍外一致
- [ ] SOP 每個操作都在 spec 裡（或列在範圍外並附原因）
- [ ] 每條測試案例可驗證：確切輸入、HTTP 狀態碼、關鍵欄位值
- [ ] 測試案例覆蓋：每個成功情境、每個錯誤代碼、冪等/並發/中斷、503/504
- [ ] 追問清單每題每個 endpoint 都有對應內容
- [ ] 自足檢查：grep 全文「比照」「見 」「沿用」「同 <另一份spec>」，
      指向 spec 外的內容一律改寫進來（SOP 路徑除外）。grep 抓不到所有寫法，
      掃完再通讀一次，確認沒有任何地方要讀者去看別份文件
- [ ] repository docstring 完整：每個方法含完整原始指令（view、欄位、排序都寫），
      grep 架構節有無「...」「等」式省略
- [ ] mock 與測試案例對齊：逐條測試案例用 mock 初始資料手動推演，
      預期結果逐欄吻合；推演不合就修 mock、修案例，或明寫 fixture
- [ ] 讀者標籤檢查：grep 全文 `Part A|Part B|給審批|給實作|給人類|給 agent`，
      零命中
- [ ] 矛盾檢查：同一 error.status 的 details 形狀全文一致；
      無「待補」「TBD」「或另外」等未定案字樣

## 盲審（Step 5）

spawn 一個乾淨 context 的 subagent（有 read-only 型就用它），prompt 照抄
（換掉路徑）：

> 你是一位實作前的規格審查者，對本專案零背景。只准讀這一個檔案：`<spec 路徑>`。
> 不要讀任何其他檔案（包括 SOP、程式碼、其他 spec），不要搜尋 repo。
> 任務：假設你要照這份規格實作，列出「實作者必須猜測或自行決定」的每一處，
> 引用原文。每條標嚴重度：兩個合理的實作者會做出不同對外行為的是 HIGH；
> 需要自行決定並記錄的是 MED；純外觀的是 LOW。嚴格，不要稱讚。
> 最後另起一節回答：只讀第 1–3 節，一個不懂技術的人能否說出這個 API 做什麼、
> 誰能用、最需要小心的操作是哪個？答不出的點列出來。

第 1–3 節讓人答不出來，視同 HIGH。

分流規則：
- 每條發現對回 spec 原文再判定；已明文的駁回並記理由（引原文）。
- 可改判嚴重度，改判記理由；後續以改判後的嚴重度為準。部分成立的 HIGH，
  只要未定義行為仍在，就算成立。
- 成立的 HIGH 大於零：修 spec（連同本輪成立的 MED），重新 spawn 全新審查者
  再審一輪；清零前不開工。
- 只有成立的 MED：修進 spec 即可開工，不強制重審。LOW 選修。
- 全部發現與處置記入 spec 同資料夾的 `REVIEWS.md`。

`REVIEWS.md` 每輪 append 一節：

```markdown
## <spec-slug> — 盲審第 <n> 輪（<日期>）

| # | 嚴重度 | 發現（引原文） | 判定 | 處置 |
|---|--------|---------------|------|------|

結果：HIGH 0 / MED 2 / LOW 1 → 通過（或：修 spec 後進第 <n+1> 輪）
```

## 實作回饋歸因（Step 6）

| 歸因 | 動作 |
|------|------|
| SOP 缺資訊 | 補 SOP 與 spec |
| skill 模板或追問清單沒問到 | 改 skill，重產 spec 該節 |
| spec 沒照模板寫 | 重產 spec 該節 |
| 純 code bug | 修 code，補對應測試 |

修完重跑 Step 4；重大修改重跑 Step 5。過程記入 `REVIEWS.md`。
